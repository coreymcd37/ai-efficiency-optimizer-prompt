# Contributing

Thanks for wanting to help make this better.

## Ways to contribute

- **Report a problem:** something unclear, outdated, or that doesn't work in a specific tool.
- **Suggest an improvement:** a new technique, a better wording, or a missing step.
- **Share an idea:** setup guides for specific tools, example runs, templates.
- **Join the conversation** in Discussions.

## Making a change

1. Fork the repo and create a branch (`git checkout -b improve-step-3`).
2. Keep edits focused: one idea per pull request.
3. Keep the style: short, direct, practical. No invented prices or model names. Use relative ratings (Free / $ / $$ / $$$) unless a figure is verified with a source and date.
4. Explain in the PR what changed and why it saves cost, time, or improves accuracy.
5. Open the pull request.

## Ground rules

Be respectful and constructive. By participating you agree to the [Code of Conduct](CODE_OF_CONDUCT.md).

## Good first contributions

New here? Look for issues labelled [`good first issue`](https://github.com/coreymcd37/ai-efficiency-optimizer/labels/good%20first%20issue) or [`help wanted`](https://github.com/coreymcd37/ai-efficiency-optimizer/labels/help%20wanted). Examples, tool setup guides, and translations are all great places to start.

## Style checks

Markdown is checked with [markdownlint](https://github.com/DavidAnson/markdownlint) using the settings in `.markdownlint.json`. You can run it locally with `npx markdownlint-cli2 "**/*.md"`.
